# SOLR-17988: document Solr 10 changes that users need to know about (upgrade notes and port docs)

Draft PR description. Not opened as a GitHub PR. The Ref Guide build has not run yet (see Proof).

## What happens today

Several Solr 10.0 changes are missing from the upgrade notes and the reference guide, so an upgrading user has no way to find them:

- Environment variables renamed or removed in 10.0 are silently ignored. The 10.0 start scripts do not read `SOLR_PORT`, `SOLR_HOST`, `SOLR_REQUESTLOG_ENABLED`, `SOLR_ADMIN_UI_DISABLED` or `SOLR_WAIT_FOR_ZK`, and they print no warning. `SOLR_HOST` is described in the note as "deprecated", although 10.0 no longer reads it.
- The port pages still describe `SOLR_PORT`. The stop port and RMI port in the control-script reference are derived from `SOLR_PORT_LISTEN`, and the cluster upgrade guide tells users to set `SOLR_PORT`.
- The SSL client authentication system properties were renamed: `solr.jetty.ssl.needClientAuth` is now `solr.jetty.ssl.need.client.auth.enabled`, and `solr.jetty.ssl.wantClientAuth` is now `solr.jetty.ssl.want.client.auth.enabled`. Neither old name has an alias, so setting it has no effect.
- The new Admin UI switches (`SOLR_UI_ENABLED`, `SOLR_UI_EXPERIMENTAL_ENABLED`) control only the new Admin UI module. The classic Admin UI is controlled by `solr.ui.enabled`.

## What this change does

Documentation only, in three pages:

- `upgrade-notes/pages/major-changes-in-solr-10.adoc`: the removed environment variables with their replacements, the Admin UI switches, the SSL client authentication renames, and one sentence on `bin/postlogs`.
- `deployment-guide/pages/solr-control-script-reference.adoc`: the port and stop-port text now names `SOLR_PORT_LISTEN`.
- `deployment-guide/pages/upgrading-a-solr-cluster.adoc`: the three `SOLR_PORT` references become `SOLR_PORT_LISTEN`.

No code or script changes. Each statement was checked against the Solr 9.10.1 and 10.0.0 trees.

The audit's suggested replacement for `SOLR_WAIT_FOR_ZK` was `SOLR_CLOUD_WAIT_FOR_ZK_SECONDS`. That is not used: no 10.0 script reads it, so the note points to the system property `solr.cloud.wait.for.zk.seconds` instead.

## Proof

Not yet. The Ref Guide build (Antora, with the `checkSiteLinks` task) has not been run. It needs a host with npm, and that run is assigned separately. The evidence for each statement is the code references in the commit messages and the subtask report, not a rendered page.

## The choice, as a question

The notes list the removed environment variables. The alternative is for the scripts to warn when one is set, as they already do for `SOLR_JETTY_HOST`. Should Solr 10 warn on the removed names as well, or is the upgrade note enough?

## Limits

- 30 further system properties that are not in the reference guide are a follow-up. They are mostly socket, buffer and pool tuning. A separate PR stacks on this one for the operator-facing subset.
- The sample text in `solr.in.sh` says `SOLR_UI_ENABLED` disables the Admin UI. The code does not do that. That is a code-comment fix and is not in this PR.
