# SOLR-17861: check SHA-1 of linux_x64 desktop runtime jars in the ui build

Draft. Not opened as a PR; opening needs owner approval.

## What

- `ui/desktopApp/build.gradle.kts`: a `linuxX64RuntimeClasspath` configuration copied from the runtime classpath, with the non-linux-x64 Compose desktop and Skiko runtime modules excluded and `compose.desktop.linux_x64` added. Adds `updateLicenses`, which writes one checksum file per external jar into `ui/licenses/`, and `validateLicenses`, which fails on a missing, mismatched or stale checksum file. `validateLicenses` is a dependency of `check`.
- `ui/licenses/`: 101 SHA-1 checksum files for the external jars on the linux_x64 runtime classpath.

## Why this shape

- The root build's `updateLicenses` aggregates the `:solr` subprojects only. `ui` has been its own build since #4650, so the check lives in `ui`.
- `compose.desktop.currentOs` resolves to the host OS and architecture. A linux-aarch64 host would get linux-arm64 jars, so the check names `linux_x64` explicitly and produces the same file set on any host.
- Checksum files are keyed by group and file name. File names alone collide: `runtime-desktop-1.12.1.jar` and `lifecycle-common-jvm-2.11.0.jar` exist under both `androidx.*` and `org.jetbrains.androidx.*` with different bytes.
- The project's own `shared-jvm.jar` is not checked. It changes with every code edit.
- No dependency coordinate was added or changed, so the root AGENTS.md rule to run `updateLicenses resolveAndLockAll --write-locks` does not apply.

## Not in this change

- LICENSE and NOTICE presence per jar, in the root's `<jar>-LICENSE-<type>.txt` form. That is license text and type decisions for 101 jars and is left for a follow-up.
- Other OS classifiers and the wasmJs yarn lock.
- `./gradlew -p ui check` needs a browser for `:shared:wasmJsBrowserTest`. CI has one; a machine without one fails there, as recorded in `reports/ui-17676-nobrowser-probe-round-1.md`.

## Verification

- `./gradlew -p ui :desktopApp:updateLicenses :desktopApp:validateLicenses :desktopApp:spotlessCheck :desktopApp:check`: BUILD SUCCESSFUL on a linux-aarch64 host with JDK 21.0.12.1. Regenerating reproduces the checked-in files byte for byte.
- Mutation: one checksum corrupted, one deleted, one stale file added. `validateLicenses` failed with all three messages. Restored; passes.
- Not run: an x86_64 host, so the file set is verified only from aarch64.
