Solr 11.0 is a major new release of Solr.

This page highlights the most important changes including new features and changes in default behavior as well as previously deprecated features that have now been removed.

== Solr 11 Upgrade Planning

Before starting an upgrade to this version of Solr, please be sure to review all information about changes from the version you are currently on up to this one, to include the minor version number changes as well.
For example, if you are currently using Solr 10.1, you should review changes made in all subsequent 10.x releases in addition to the 11.0-specific changes on this page.

== Removed Features

=== Overseer Roles API

The `ADDROLE` and `REMOVEROLE` Collections API commands have been removed, together with their V2 `add-role` and `remove-role` counterparts, the `CollectionAdminRequest.addRole` and `CollectionAdminRequest.removeRole` SolrJ methods, and the `roles` section of the `CLUSTERSTATUS` response.
The `/roles.json` node in ZooKeeper is no longer read or written; an existing one is simply ignored and may be deleted.

Overseer designates are now declared at startup with node roles, for example:

[source,bash]
----
bin/solr start -Dsolr.node.roles=data:on,overseer:preferred
----

A node started this way asks the Overseer to re-run its node prioritization, so a preferred node takes over without waiting for the current Overseer to restart.
Note that node roles are fixed for the lifetime of a node: unlike `ADDROLE`, they cannot be changed on a running node.

== SolrJ

=== NamedList is a sealed class

`NamedList` is now a sealed class whose only permitted subclass is `SimpleOrderedMap`, which is `final`.
Plugins or client code that extended either class will no longer compile; hold a `NamedList` rather than being one.

`CloudSolrClient.RouteResponse` has been removed.
A routed update request now returns a plain `SimpleOrderedMap`, whose `responseHeader` carries the achieved replication factor of each route under `rfByRoute` (`CloudSolrClient.REPFACT_BY_ROUTE`), keyed by route URL.
`CloudSolrClient.getShardReplicationFactor()` reads that entry, so its signature and behavior are unchanged; `condenseResponse()` now returns a `SimpleOrderedMap`.

=== ContentStream moved from SolrJ to solr-core

`ContentStream` and `ContentStreamBase` are no longer part of SolrJ.
They now live in `solr-core`, in the package `org.apache.solr.util` instead of `org.apache.solr.common.util`.
Plugins that use them, for example custom request handlers or update processors, must update the import and be recompiled against Solr 11.
`ContentStream` is no longer deprecated: it is the server-side contract for reading request content.
SolrJ clients write request content with `RequestWriter.ContentWriter` instead.

The unused `ContentStreamBase.create(RequestWriter, SolrRequest)` and `ContentStreamBase.setSize(Long)` methods have been removed.

== Response Format

=== Some admin response sections are JSON objects regardless of json.nl

Solr builds many response sections as a `NamedList`, which the JSON response writer renders according to the `json.nl` parameter (by default as a flat array of alternating names and values).
Sections whose names never repeat are now built as a `SimpleOrderedMap` instead, which the JSON writer always renders as a JSON object, exactly as `json.nl=map` did before.
Clients that read these sections with the default `json.nl=flat` (or with `arrarr` / `arrmap`) must now read a JSON object; clients using `json.nl=map`, XML, or SolrJ (javabin) see no change.
The affected sections are:

* `OVERSEERSTATUS`: `overseer_operations` and `collection_operations` are objects keyed by operation.
* `LISTSNAPSHOTS` (v1 Collections API): `snapshots` is an object keyed by snapshot name, and each snapshot and its `replicas` entry are objects.
* `DELETEBACKUP` with `purgeUnused`: the `deleted` summary (`numBackupIds`, `numShardBackupIds`, `numIndexFiles`) is an object.
* `INSTALLSHARDDATA`: the entry reported for a replica that is recovering from its leader after a failed install (`explanation`, `failure`) is an object.
* Replication handler `deletebackup` (named snapshot): the command's details (`startTime`, `snapshotName`, `status`, `endTime`) are an object.

Sections designed around repeated or user-controlled keys, such as the `success` and `failure` lists of Collections API responses, classic facet counts, the terms component, spellcheck, term vectors and `sort_values`, are unchanged and still follow `json.nl`.
