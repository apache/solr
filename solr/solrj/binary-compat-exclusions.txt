# Intentional binary-incompatible SolrJ changes, excused for the
# binary compatibility check in gradle/validation/binary-compat.gradle
# (SOLR-18600). The check compares the built jars against the previous
# release (10.1.0 unless the solrj.binaryCompat.baselineVersion
# property says otherwise) and fails on any binary-incompatible change
# that no entry here covers. An entry that covers no current change
# draws a warning, so stale entries get noticed instead of rotting
# silently.
#
# One entry per line, four fields separated by ';':
#
#   <fully qualified class> ; <japicmp change type, or *> ;
#       <member name substring, or *> ; <ticket and reason>
#
# The ticket and reason field is required: an intentional break is a
# decision, and the entry is where the decision is recorded. Change
# types are the japicmp names, for example CLASS_REMOVED,
# METHOD_REMOVED, FIELD_REMOVED, CONSTRUCTOR_REMOVED,
# METHOD_RETURN_TYPE_CHANGED or FIELD_TYPE_CHANGED.

# read as changes, because 10.1.0's narrowed shapes were the break
# being fixed; these entries excuse exactly that restoration.
