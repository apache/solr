= Browsing the V2 API with the API Explorer

Solr's v2 (JAX-RS) API is described by an OpenAPI spec generated at build time
from the annotated interfaces in `solr/api/src/java/.../client/api/endpoint`.
The API Explorer is bundled in the Admin UI and renders the generated spec using Scalar.
It's loaded in an iframe from `solr/webapp/web/libs/scalar/index.html` rather than mounted
directly into the Angular app: Scalar manages its own URL hash for deep-linking to operations,
which conflicts with AngularJS's `ngRoute` (both rewrite `window.location.hash`), causing an
infinite digest/navigation loop. A dedicated document/window avoids the conflict entirely.

== Usage

Build and start a local Solr with `./gradlew dev` and `bin/solr start -c`.
Open the *API Explorer* item in the Admin UI's left nav to browse endpoints and send requests.
The page and its assets are served locally; API requests go directly to the same Solr origin.
Executing a request can change the running instance, just as calling its API directly can.

Rebuild the webapp after changing API annotations to refresh the explorer's spec.

== Maintaining Scalar

`solr/webapp/scalar` downloads the `@scalar/api-reference` npm package at build time and
copies its `dist/browser/standalone.js` into the webapp's war, so the bundle is never
checked into source control. Its version is recorded as `scalar-api-reference` in
`gradle/libs.versions.toml`; bump that version to upgrade, and review the new version's
license and bundled dependencies. The MIT license text is recorded in the root `NOTICE.txt`.
The initializer lives in `solr/webapp/web/libs/scalar/scalar-init.js` as a
separate script so it also works with a policy that disallows inline scripts.
Default CDN fonts, the request proxy, AI chat, hosted-client links, developer tools, and telemetry are disabled.
